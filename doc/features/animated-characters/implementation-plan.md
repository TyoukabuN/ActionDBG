# 实施计划

依据：[需求](prd.md)、[设计](design.md)。采用完整流程，本轮仅替换角色和表现适配。

1. 准备：核查固定来源、CC0、原文件与动画；选择必要动作，保留可重复准备脚本、哈希和许可。运行静态 GLB 结构与引用检查。
2. 模型适配：新增 `src/characters.ts` 及其测试，隔离骨骼姿态取样、武器选择、归一化、根运动与资源释放。不得修改 Combat 或依赖。
3. 场景集成：在 Arena 异步接入、提示加载／降级、保持渲染层与生命周期；对齐当前攻击、格挡、受击、反击和胜负边界，保留输入与队列。
4. 验证：类型／全部单元／生产构建；真实输入验证两个模型加载、不同骨骼姿态、连续行动与暂停／重开、格挡和反击、失败降级，以及桌面／竖屏截图和动作序列；记录渲染统计。审查差异后直接推送 main，托管部署另行核实。

风险：遗漏纹理、骨骼命名／根运动错误、互斥武器同时出现、模型尺寸或朝向错误、异步销毁泄漏、动作与伤害脱节、加载失败阻断玩法。

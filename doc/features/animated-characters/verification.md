# 角色替换验收

日期：2026-10-15。状态：本地验证完成。上游：[需求](prd.md)、[设计](design.md)、[实施计划](implementation-plan.md)。

## 已执行

- 资产：从作者固定 Git 提交读取 CC0 正文；准备脚本通过固定原始 SHA-256 检查，重复执行产生相同输出。裁剪后的两个 GLB 可由 Three.js GLTFLoader 解析，各含 12 个必要剪辑。
- 保真：对原始与准备后文件执行 5,882 项网格／动画输入输出／嵌入贴图数据比较，全部相同。处理仅移除未引用的动画与数据，运行时才筛选装备并处理根水平位移。
- 单元：42 项通过（26 Combat、8 镜头、8 CharacterVisual），包括真实 GLB 结构、装备／比例、时序、骨骼矩阵实际变化、根 XZ 固定而 Y 保留、暂停、终局、缺失剪辑拒绝及资源唯一释放。Node 纹理解码使用桩，仅证明结构与数学；浏览器另行验证真实贴图。
- 类型／生产构建：通过。GLTFLoader 由现有 Three.js 提供，无新增 npm 依赖。主 JS 约 695 kB／183 kB gzip，Vite 仍提示大于 500 kB；两角色合计 1,686,176 字节。
- 初轮生产浏览器：4 项通过（3.2 分钟），覆盖真实骨骼角色、连续出牌、反击、暂停／重开、格挡受击、390×844 触控和故意中止 Knight 请求后的降级。初轮截图发现头盔遮挡及素材接触段取样不准，已继续修正，不能将初轮截图当成最终构图证据。

## 复查与限制

使用现有 Playwright 真实输入与诊断，不向生产页面注入强制战斗状态的测试钩子。角色功能仍处于原型迭代，不建立用户尚未接受的截图基线，也不宣称发布级美术或真实设备 FPS。按 threejs-qa-release 进行连续未暂停模拟动作取证，重点检查足部／根运动、武器接触、收势和骨骼变形。

修正后受影响的 3 项浏览器场景再次通过（3.0 分钟），包含连续骨骼出牌、反击之后不补播敌方攻击、暂停／重开、持续举盾／真实格挡受击和竖屏触控。失败加载场景与此后的动作时序／构图修改无关，复用初轮通过证据，没有重复计数。全部共 4 项不同角色浏览器场景；未重跑上一轮全部整局胜负浏览器测试，规则仍由原 26 项 Combat 测试覆盖，终局剪辑映射由 CharacterVisual 测试验证。

最终连招取证保存 18 张连续未暂停模拟帧，覆盖快斩准备、接触、收势及后续重斩的完整周期，间隔最大 100ms。游戏没有被强制设置为动作状态，全部由数字键与按钮提交；截图时暂停的是测试调度时钟，没有设置游戏 paused 标记。逐段检查没有 T 姿势、塌陷肢体、重复武器或根位移双倍叠加。依旧是素材动作加短突进的首版，没有足部 IK、物理接触求解或逐招手工动画打磨。

已审查最终桌面／竖屏、接触、反击与格挡截图。角色在黑边前、血液／火花在最后通道；手机仍能看到敌人面部、武器方向及操作区，无横向溢出。证据位于 `/tmp/actiondbg-characters-20261015/final/`，文件清单与独立生产活动帧诊断保存在 `manifest.json`；这些临时图像未提交。导入检查的完整采样峰值为 137 次绘制调用、45,834 个三角形、116 个几何体、7 张纹理（接触段修正前、相同角色资产）；不是 FPS 或实体手机性能承诺。四个合成通道、无后处理、一个 1024² 阴影光源及 DPR 上限 2 保持原设置。本地构建及推送不代表托管 CI／Pages 已部署成功。

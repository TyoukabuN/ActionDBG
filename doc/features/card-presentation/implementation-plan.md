# 正式牌面：实现计划

上游：[需求](prd.md)。状态：可实现；标准流程；2026-10-15。

## 视觉方案

牌面采用锻造青铜边框、深色标题、独立插画窗口和旧纸效果区，沿用竞技场的青绿与铁锈红。色板：墨色 `#172628`、铜色 `#a98a58`、纸色 `#dfd1af`、暗红 `#713b31`、青绿 `#416d64`、金色 `#e0be84`。中文牌名使用系统宋体族，规则使用系统黑体族，费用使用衬线数字；无需联网字体。

结构为“左上费用＋标题 / 插画 / 类型窄条 / 规则效果 / 快捷键＋状态”。强调视觉只放在牌面及插画，其他界面保持现有风格。桌面四牌横排并控制宽度，禁止拉伸成网页信息块；手机使用单排原生横滑和可见滑动提示，避免两排大牌挤掉战斗场景。完整状态留在牌内，不靠颜色独立传达。减少动态偏好下禁用抬升动作。

## 阶段与验证

1. 技能和资产：核对 `frontend-design`、`card-game` 与已有 UI 技能；安装最适合牌面视觉的前者并保留固定提交和许可证。生成四格原创插画，拆为四张 WebP，记录来源、生成提示和摘要。关联 FR-001、FR-004。
2. 有界实现：只改 `src/main.ts` 的牌面结构、`src/style.css` 的牌面及手牌响应式规则。复用现有卡牌定义和状态渲染，清理相互冲突的旧牌面断点规则；保留原按钮标识和事件。插画通过基础路径解析。关联 FR-001 至 FR-004。
3. 审查：主线程审查实际差异，运行类型、单元测试和构建；生产预览检查桌面、竖屏、横屏及图片失败。复用现有战斗测试覆盖入队、反击和旧模式；保留截图作为本地审查证据。对应 AC-001 至 AC-004。

实现依赖第一阶段的技能和插画完成。风险主要为较高牌面占用空间、手机横滑可发现性、长状态文字和旧 CSS 优先级；以尺寸、截断检查和真实点击验证处理。代码修改不涉及战斗状态机，若需要改规则或输入生命周期则返回主线程。

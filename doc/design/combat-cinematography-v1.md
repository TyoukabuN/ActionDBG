# 战斗镜头设计第一版：压住、切开、落定

日期：2026-10-15。状态：待试玩的分镜方案，**尚未实现**。
依据：[当前战斗设计](../features/cinematic-qte/design.md)、[镜头技能研究](../research/combat-camera-skills-2026-10-15.md)。本次使用 [cinematic-director](https://github.com/wuwangzhang1216/DirectorSKILL/blob/c65ae0d14457053efb1e354c7e7f7e120d97fad1/SKILL.md) 的分镜设计模式，实际阅读其镜头语言、调度、镜头表、剪辑及制作难度参考。技能正文和参考沿用研究阶段固定提交的本地读取副本；未安装或运行其媒体生成工具。

## 演出意图

让玩家先看见“力量蓄在哪里”，再看见“力量怎样经过对手”，最后看见“对手为什么被打退”。视觉主张：**画面先压住，攻击把画面切开，结果在一个稳定画面中落定。** 漫画感来自主次、景别反差、动作方向和停留，不要求每个镜头都倾斜或运动。

本版重点设计重斩与反击，快斩和格挡使用简化版本。沿用程序化角色、石质竞技场、青绿玩家／锈红敌人和右肩常驻视角；没有面部表演时，用头盔朝向、肩线、剑路和身体重心讲清动作。

## 先排动作，再摆相机

- 待机：玩家在近处偏左，对手在远处偏右。双方脚下位置和一段地面建立距离；玩家肩背是画框，不是半幅不透明墙。
- 重斩：玩家重心先后压、剑抬到右肩上方，再沿既定攻击方向踏入并下斩；命中后刀路继续向低处走，对手上身和重心沿受力方向退开。镜头不能代替身体接近。
- 反击窗口：敌人已经逼近，刀锋停留在将要进入玩家防线的位置；玩家保持可反切的预备姿势。是否实际反击仍由输入决定，预备姿势不产生格挡效果。
- 反击成功：玩家用一次反切命中敌方持剑前臂，同时把来刀带偏；“伤害”和“取消来袭”由同一动作解释。不给立即生效的规则硬加一个先架刀、隔一拍再刺人的延迟。
- 格挡：来刀碰到盾牌，盾与前臂后压，脚下重心稳住；命中环和金属火花都从实际接触位置出现。

几何前提：未来实现必须从武器／前臂／盾牌的世界坐标确定接触点，调整纯表现走位，使攻击在结算帧真实到达目标轮廓。不能只把镜头对准两人之间的空地并在那里喷粒子。表现走位不改变目标、费用、伤害或回合顺序，收势回到原站位时不得突然跳回。

## 全片共用的镜头规则

| 项目 | 本版约定 |
| --- | --- |
| 空间方向 | 以双方连线为战斗轴，所有常规机位留在观众这一侧。玩家进攻始终由画面左／近处进入右／远处，敌人反向；不为追求变化随意越轴 |
| 常驻画面 | 玩家右肩过肩中景；前景肩背占画面宽度约 15–25%，不遮对手持剑手、来刀和接触区域；允许裁掉部分玩家身体，不要求一直全身入镜 |
| 景别分工 | 常驻交代关系，发力中景看剑路，接触近景看攻防结果；不用原型脸部特写承担情绪 |
| 硬切 | 发生在身体开始发力或接触事件上；主动改变角度或景别，让观众知道换了镜头，不从任意旧机位滑穿场景 |
| 运镜 | 单镜最多一种主导运动：缓推、短侧跟或锁定。决策段停止漂移；不叠加推近、环绕、大倾斜和强抖动 |
| 倾角 | 常驻为 0°。重斩接触或反击结果可用一次约 3–5°倾角，同一动作不来回晃；具体数值需预演检验 |
| 光线与色彩 | 保留世界中同一主光和阵营色，换机位不翻转灯位；轻击、格挡、反击用形状／动作区分，颜色只作辅助 |
| 转场 | 关系镜头到动作镜头用有动机的硬切；动作落定回常驻可用约 100–160ms 的短回归。删除统一套用 180ms 插值的规则 |

这些是构图起点，按真实画布和 HUD 检查，不把电影焦距数值直接当作 Three.js 的垂直 FOV。先确定主体在画面中的大小及机位距离，再解算投影。

## 重斩分镜：让重量经过对手

`t = 0` 为玩家接受重斩输入。保留现有 550ms 行动及伤害边界；之后最多约 240ms 只是可中断的表现收势，不锁定输入，也不暂停已经恢复的玩家选牌计时。

| 镜号／时间 | 节拍及用途 | 画面、动作起止 | 镜头运动与切点 |
| --- | --- | --- | --- |
| H1 · 0–180ms | 蓄力；让人读懂承诺 | 玩家右后侧偏低的中近景，持剑手和剑柄占左下，对手上身保持在右上。玩家后压、右肩收紧，剑到达右肩上方后停住；终态是重心压稳、刀路即将释放 | 输入时切入；锁机位，让角色自己改变轮廓。不要给蓄力同时加抖动 |
| H2 · 180–550ms | 发力；解释距离和剑路 | 切到同侧约偏转 35–50°的双人中景。玩家左、敌人右；踏入和下斩形成一条清楚斜线，剑尖及敌方受击侧均可见。最后一帧刀锋抵达受击轮廓 | 180ms 身体开始前冲时硬切。只做一次短侧跟，幅度不超过约 0.15 个角色身高；到 550ms 必须看清接触，不让肩背或卡牌遮住 |
| H3 · 550–790ms | 命中与余势；给结果重量 | 以接触点为锚切至双方前臂／躯干近景，仍留一段武器和对手肩线交代方向。伤害、短命中反馈、血粒子在 550ms 同时出现。玩家刀继续下压，对手重心后退；末态是力已释放、两人轮廓分开 | 命中边界硬切，接触位置在切前后尽量保持同一画面区域。先锁住约 60–80ms 的构图，再允许角色完成收势；不是冻结模拟。后半段可回归常驻，新出牌立即接管镜头 |

节奏读法：**“压——斩！退。”** 180／370／240ms 总计 790ms 的可见段落，玩法行动仍为 550ms。若预演无法在该长度内读清动作，另行提出动作时长调整，不暗改规则。

## 敌人出牌与反击分镜：被压迫，然后夺回主导

敌人出牌的前摇沿用轻击 1.1 秒／重击 1.6 秒；有合法反击才进入 2 秒窗口。右上角敌方卡牌从提交开始显示，与是否开启反击无关。

| 镜号／时间 | 节拍及用途 | 画面、动作起止 | 镜头运动与切点 |
| --- | --- | --- | --- |
| C0 · 敌方前摇 | 威胁正在接近 | 常驻过肩关系镜头。敌人踏入，持剑手和肩线由远处压近；结束时刀锋与玩家防线关系清楚。右上卡牌入场，但不覆盖持剑手 | 以角色运动制造接近感，机位保持稳定；不在卡牌入场时另作一次无关环绕 |
| C1 · 反击窗口前 160ms，随后稳定 | 看见“即将命中”的压力 | 在同一侧沿右肩方向推进一档景别，玩家肩缘让出中心，对手刀锋／前臂成为焦点；黑边按既有斜向路径进入。之后停在可读预备姿态，不让刀锋穿过角色 | 只做一次短推，160ms 内落定。2 秒反击计时从窗口真正开启开始，运镜不增加等待、不延后按钮可用时间 |
| C2 · 按下反击起 0–80ms | 夺回主导；取消发生在接触上 | **输入帧立即硬切到反切接触近景。** 玩家刀进入敌方持剑前臂，来刀向外偏开；同帧结算既有 2 点伤害、取消来袭并出现命中粒子。构图中保留两把武器的方向，不只拍一团光 | 快速输入即打断 C1，不要求玩家等镜头／黑边到位。接触近景短暂锁定，允许小幅表现冲量；血液与接触都在输入帧，不延迟到后续补刀 |
| C3 · 输入后 80–420ms，随后回归 | 结果与余波；敌人的攻击线被破坏 | 同侧中近景看见敌人持剑臂被带开、躯干后退，玩家剑停在身前；终态为玩家重新守住中线、敌人失去攻击线。黑边保留到反击结算段结束，随后退出 | 80ms 切到清楚的结果画面，保持轴线；不用连续绕两人旋转。420ms 后自然回常驻，遵守现有 650ms 敌方结算与回合结束流程 |

快速按下反击时，C1 可以缩短甚至跳过；C2／C3承担结果表达。放弃或超时则不播放成功反切：转入敌方攻击，刀锋在现有 650ms 结算末端接触玩家／盾牌，同帧结算伤害或减伤。反击不可用时，从 C0 直接进入该攻击段，不出现黑边、空反击窗口或普通 Response。

## 快斩与格挡的简化版本

- **快斩：** 维持右肩中景，角色快速踏入；550ms 接触时最多切一次短命中近景，随后迅速回归。它比重斩少一个蓄力镜头，不能每张牌都演成必杀技。
- **格挡出牌：** 用原右肩机位或短切到盾侧，表现盾抬起并稳住；此时只建立防御状态，不提前喷火花。敌方来刀实际触盾的结算帧，才短切盾／刀接触点，金属火花向外散，盾后压、玩家不失去站位。

## 横屏与竖屏分别构图

画幅指战斗画布，**手机页面竖屏不等于战斗画布必然为 9:16**。以运行时画布宽高比和实际遮挡区计算取景，不通过设备名硬套电影格式。

- 横向画布：重斩 H2 可用双人侧面关系，保持玩家左、敌人右；肩背不要挤掉敌人的攻击手。
- 较窄画布：用前后纵深，玩家肩缘在左下、对手持剑手在中上；H2 减少横向位移，改沿斜向纵深入场。不能只拉远把两人都缩成小人，也不能直接中心裁切横屏镜头。
- H3／C2 的接触点优先放在实际无遮挡区中间；右上敌方卡牌、上方生命 HUD、下方阶段／计时各自形成排除区。头盔可以部分出画，剑路、接触点和伤害反馈不能被卡牌遮住。
- 黑边仍按“场景 → 黑边 → 角色 → 粒子”绘制。角色能压住黑边不等于可以被 HUD 遮住；若画布过矮，先减少前景肩背、调整接触构图，再考虑缩窄遮幅，不能把中部挤成不可读细缝。

## 实现边界与审查方法

本次交付是镜头方案，不修改状态机、AP、冷却、决策时限、伤害边界或游戏代码。未来由现有 Three.js 表现层将动作节拍映射为镜头段落：镜头有用途、主体锚点、进入／退出条件、切换类型和稳定终态，不再只有每阶段一组世界坐标。时间使用现有行动进度和结果事件；暂停冻结，重开清空，降低动态效果采用稳定关系镜头和同样的接触反馈。

使用的是该技能的精简镜头表，省略视频生成模型、片段收费和生成风险分数：已阅读其难度量表，但本案是确定性实时 3D，不拿生成成功率分数冒充运行时验收。保持原场景光线与资产连续性，不增加视频生成服务、音频或新角色模型。

未来预演需完成以下检查，当前均**未执行**：

1. 连续录像对照同一张重斩／反击的旧版与本版，分别检查起手、发力峰值、接触、收势，不能仅凭分镜编号变化判定成功。
2. 接触帧武器实际到达目标；建议投影间隙不超过画布短边约 1%，切前后接触锚点漂移不超过画布宽度约 10%，超标先修调度／取景。这些是首轮检查阈值，尚未实测。
3. 550ms 重斩伤害、输入帧反击、650ms 敌方攻击伤害均与可见接触一致；不得为了等镜头而丢输入、延后结算或冻结倒计时。
4. 横屏与手机窄画布分别查看 HUD 排除区、对手持剑手、接触点；快速反击、连续出牌、致死、暂停和重开不残留上一镜。
5. 真人只比较三件事：重斩是否有重量、反击是否看清如何破招、镜头回到选牌时是否舒适。没有试玩结果前，不宣称本版已经改善手感。

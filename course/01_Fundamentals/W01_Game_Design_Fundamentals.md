# W01 游戏设计基础：把想象中的体验写成可执行的规则

## A 学习目标

完成本周后，你应能够：

1. 区分目标体验、游戏目标、规则、执行程序和实现方式，不把“战斗很爽”写成已完成的机制设计。
2. 用玩家、目标、资源、冲突、边界、结果等形式元素拆解一款卡牌游戏。
3. 为一个选择列出状态、已知信息、合法动作、结算顺序及不同后果，发现关键歧义。
4. 解释“可点击的选项多”为什么不等于“有策略选择”，并给出受情境约束的分析。
5. 写出一份可独立执行的纸面规则，完成两条不同决策路径的推演，记录一次外部试玩的观察与未知问题。

掌握的证据是规则、推演和解释。本周不要求证明长期趣味性或实现新功能。

## B 前置知识与程序员视角的调整

你已有变量、条件判断和程序执行顺序的直觉，这很有用。可以把“玩家有 3 点行动点”理解为一个状态，把“支付 2 点才能重斩”理解为合法性条件。但是，程序正确只能说明系统按某种规则运行，不能说明这组规则值得玩家探索。

设想你写完一个严谨的卡牌结算器，每张牌都准确扣费，动画也完整播放。如果所有攻击牌同费、无其他差别，只有伤害不同，玩家很快可能只点伤害最高的那张。工程任务完成了，设计问题仍然存在。相反，纸上三个数字就可能暴露出真实取舍，无须等完整界面做完。

本周只依赖基础算术和顺序推理。以下三个区别需要先记住：

- **发生了什么**：玩家连续三次选择攻击，是观察。
- **为什么发生**：玩家认为格挡不划算，是一种解释，尚需询问或比较其他证据。
- **希望发生什么**：玩家应在攻防间犹豫，是设计意图，不是事实。

## C 核心理论

### C1 游戏设计在设计什么

“什么算游戏”在研究中没有一个能无争议覆盖所有作品的定义。有人强调规则、冲突和可量化结果，有人重视自愿参与、虚构情境或游戏态度。叙事探索、沙盒和角色扮演会挑战其中某些边界。初学时不必先解决这个哲学问题。

本课程采用一个**工作定义**：游戏设计是在特定参与情境中，组织玩家的行动、限制、信息和后果，使玩家产生预期但需要验证的活动与体验。这个定义服务于当前 DBG 学习，不宣称所有游戏都必须有输赢、敌人或有限资源。

为什么要把“活动”与“体验”分开？你能规定玩家每回合只能出两张牌，却不能规定他一定感到紧张。新手可能困惑，熟练玩家可能迅速算完，另一个人可能喜欢从容规划。同一规则经过理解、技能和情境的作用，才形成实际体验。设计师能直接修改规则和呈现，不能直接把某种情绪写进玩家脑中。

因此，“加入反击牌，让玩家感觉自己抓住破绽”至少包含两部分。可以落实的部分是反击何时合法、需要什么资源、改变什么结果；有待验证的部分是玩家能否识别机会、是否认为值得、是否把结果归因于自己的判断。前者不能代替后者。这也是下周研究 MDA 的起点。

### C2 用形式元素找到系统骨架

形式元素（Formal Elements）帮助我们暂时抽去题材和特效，检查参与结构与规则关系。Fullerton 的教材将形式元素作为分析游戏的重要入口；下表以自己的语言整理常用维度，不是原著逐字定义。

| 元素 | 要回答的问题 | 在卡牌战斗中的具体含义 |
| --- | --- | --- |
| 玩家 Players | 谁参与、谁控制什么、参与者怎样关联？ | 玩家控制角色，敌人按规则行动；是否合作或竞争需明确。 |
| 目标 Objectives | 玩家想达成什么结果？ | 击败敌人、保护目标或满足特殊条件，不能只写“不断出牌”。 |
| 程序 Procedures | 行动按什么流程展开？ | 谁先行动、何时选牌、何时结算、何时进入下一回合。 |
| 规则 Rules | 哪些状态合法、何种动作被允许、后果如何产生？ | 费用不足不得出牌；攻击造成伤害；死亡后不继续行动。 |
| 资源 Resources | 什么会被获取、占用、支付或失去？ | 生命、行动点、手牌、抽牌机会；不同资源恢复方式不同。 |
| 冲突 Conflict | 什么阻碍目标达成？ | 敌人伤害、有限行动预算、相互排斥的选择，而不只是画面上的打斗。 |
| 边界 Boundaries | 哪些人、信息与行为属于本局？ | 是一场遭遇还是整段冒险？局外选择是否影响本局？ |
| 结果 Outcome | 系统怎样识别结束，如何评价结果？ | 胜负、得分、是否保留剩余生命；没有定义的指标不自动算成绩。 |

这些元素需要相互解释。说生命是资源，还必须问它如何损失、是否能恢复、归零代表什么。如果一局只有胜负，没有跨局生命继承和剩余生命评分，那么“赢时保留更多生命”未必是规则激励，可能只是玩家个人偏好。分析时要把这两者分开。

形式分析也有局限。它无法单独解释角色身份、音乐或文化背景怎样赋予行动意义。我们暂时抽离它们，是为了定位规则问题；不是说它们对完整体验不重要。W09–W10 会把玩家解释与信息呈现重新纳入。

### C3 区分四种常被混写的目标

第一种是**体验目标**：希望谁在何种情境中感到什么，例如“让熟悉回合制的新手觉得，自己因读懂敌人而取胜”。它描述方向，不能直接由一个布尔值判定。

第二种是**游戏目标**：系统认可的任务，例如“在生命归零前使敌方生命归零”。它约束玩家优化什么。第三种是**局部目标**：玩家为整体目标采用的临时办法，例如攒够资源买牌、避免本次受伤。局部目标可能被推翻：若本回合击杀能直接获胜，提前结束战斗可能比继续格挡更好。

第四种是**项目目标**：设计者这次要验证或交付什么，例如“验证玩家是否看得懂反击窗口”。它不是玩家的胜利条件。把项目目标塞进游戏目标，会出现“为了让设计者看到新机制，玩家必须按指定顺序出牌”的问题：你测到的可能是服从教程，而非自然选择。

一个实用判断是：当两个目标冲突时，规则究竟奖励哪一个？若口头鼓励冒险，却按每点受伤永久扣分，玩家保守并不奇怪。问题可能是目标结构不一致，而不是玩家“不懂设计意图”。本周只需要发现冲突，如何量化取舍留到 W07。

### C4 状态、动作与结算：让规则能被执行

游戏状态（Game State）是描述当前局面、使规则能够决定后续变化所需的信息。对一个简化决斗，它可以包含双方生命、当前行动方、行动点、可用牌、护盾和回合数。背景石柱颜色若不影响任何规则，通常不属于这个规则模型；隐藏的下一张牌仍可能属于完整状态。

动作（Action）是玩家或系统允许进行的一次操作。必须区分“点击了重斩”和“合法地打出了重斩”：费用不足时前者可以发生，后者应被拒绝。把输入当作已承诺行动，会让推演无法解释资源何时支付。

可以用以下记法帮助阅读，不需要编写算法：

$$
s_{t+1}=T(s_t,a_t)
$$

这里的 $s_t$ 是结算前的状态，$a_t$ 是合法动作，$T$ 是状态转换规则。若有抽牌随机性，转换还依赖随机结果；若有同时决策，则不能只用一个人的动作描述全部情况。这个最小模型是记账工具，不是所有游戏的完整数学定义。

还要区分完整状态与玩家当时知道的信息。玩家通常不知道对手暗牌，但可以据已公开的信息做决定。评价“他应该选择哪张牌”时，不能偷偷把结算后才揭示的信息算进他的知识。否则你比较的是事后答案，不是实际决策质量。

以“敌方剩余 2 生命，玩家重斩造成 3 伤害”为例：扣费后敌方降为零，是否立即结束？若敌人原本准备出手，攻击还会继续吗？两种顺序都可以成为设计，但必须明确。规则写“双方发动攻击”仍不足以确定先后，更无法让陌生人重现结果。

### C5 规则不仅是牌上的效果文字

本课把规则规范分成四组检查问题：合法性、结算、信息、终止。这是教学用检查工具，不是从某本书直接搬来的通用分类。

合法性规定什么时候能做什么；结算规定支付、目标、效果与后续事件的顺序；信息规定玩家在决定前后能看到什么；终止规定何时停止并如何判定结果。卡牌效果通常只覆盖其中一部分。

例如“反击：取消敌方攻击并造成 2 点伤害”尚未说明：哪些攻击能触发，反击是在命中前还是命中后，是否消耗普通行动资源，无法支付时窗口还开不开，双方同时死亡如何处理。缺失部分会被程序员、玩家或主持人各自补上，不同补法会产生不同游戏。

程序与规则也不完全相同。“玩家回合 → 敌人回合”是流程骨架；“只能在自己的回合打普通牌”是合法性约束。为了便于阅读，可以分开写；为了可执行，二者必须一致。流程图若允许进入反击，规则却没有任何合法反击动作，漂亮的图也没有解决问题。

规则不要求玩家界面展示所有内部细节，但设计者必须知道细节如何影响决策。比如资源在“己方回合结束”恢复，与在“下次己方回合开始”恢复，会改变敌方回合能用多少资源。资源上限相同，不代表两套规则具有相同取舍。

### C6 什么样的选择具有设计意义

选择（Choice）首先要求存在不同的可执行方案。决策（Decision）还涉及玩家依据目标、信息与预期后果进行取舍。按钮数量、排列组合数量或输入频率都不能直接衡量策略深度。

Salen 与 Zimmerman 在有意义的游戏行为（Meaningful Play）讨论中强调行动与结果之间的关系，包括结果是否可辨认、是否整合进更大的游戏系统。本课据此提出两个检查问题：玩家能否理解“这个变化与我的行动有关”？这个变化会不会影响之后的局面或目标？这是转述与教学应用，不是声称两个问题足以定义所有有意义选择。

若重斩比快斩多扣生命，但界面只播相同的光效，玩家可能感受不到差异。若两种牌只是火焰颜色不同，随后状态完全一致，也许提供表达偏好的价值，却没有相同意义上的战术取舍。表达选择可以很好，但不要用“多了一种策略”描述它。

再考虑两张同费牌，甲造成 4 伤害，乙造成 2 伤害。若两者可用条件、目标、次数、后果全部相同，且唯一目标是尽快减少敌方生命，乙在这些前提下不占优势。我们暂称它被甲支配，严格条件将在 W08 讨论。若乙还能抽牌、绕过护甲或避免反伤，前提就变了；不能只看一个数字宣布它没用。

“每次都要纠结”也不是唯一理想。让新手识别明显好牌，可以服务于学习；让高手快速执行已理解的组合，可以服务于流畅感。要评估的是重复游玩后是否仍存在符合目标的判断，及其成本是否值得，而非强迫每秒做困难选择。

### C7 策略深度、复杂度与不确定性

规则复杂度与策略深度需要分开看。增加三种费用和十种关键词，会增加记忆与组合数量；如果一种组合在所有相关情境下都明显最好，新增复杂度可能没有产生你希望的判断空间。反之，少量规则也可能因时机、位置、对手与资源关系形成丰富选择。

不确定性也不等于随机性。洗牌产生随机结果；隐藏敌方计划产生信息不足；知道全部规则却无法立即穷尽后果，则属于计算和推理上的困难。它们可能同时出现，但改进办法不同：说明界面能解决信息表达问题，却不能消除洗牌的随机性。

本周不计算抽牌概率，只问某项不确定性服务于什么。它是否使玩家需要调整计划？是否提供可以管理的风险？玩家能否理解损失的原因？完全确定的短决斗可以是有价值的战术谜题，随机发牌的战斗也可能每次都只有同一个答案。因此不能用“每局不一样”直接证明重玩深度。

### C8 从设计主张到可反驳的问题

设计主张应允许自己被证据修正。“反击很有趣”过于宽泛；“首次接触规则的玩家，看到攻击提示后，能说明为何选择反击或放弃”更便于观察。但即便有人能解释选择，也不能据此证明紧张感或长期耐玩性。

本课建议把主张拆成四项：预期行为、发生条件、观察办法、可能推翻它的证据。例如，预期玩家在高威胁时防守；条件是威胁已公开且防守规则被理解；观察其出牌与解释；若玩家认为无论威胁多少都只有同一个可行选项，便要检查机制是否真有情境差异。

## D 案例研究

### D1 成熟游戏：Dominion 为什么把得分牌放进牌库

以下事实依据基础游戏第二版规则，讨论双人、无扩展情形。每位玩家用 7 张铜币（Copper）和 3 张庄园（Estate）组成起始牌库，洗牌后抽 5 张。一个回合依次进行行动、购买、清理；默认有一次行动和一次购买机会，卡牌可改变它们。清理时弃掉手牌与已打出的牌，再抽 5 张，牌库不足时按规则利用弃牌堆洗牌继续抽。

普通购买得到的牌放入弃牌堆，通常不会立刻成为本回合手牌。基础胜利牌庄园、公国、行省贡献终局分数，却通常不提供该回合的行动或购买力。双人基础游戏在回合结束时检查行省堆耗尽或任意三堆供应牌耗尽等结束条件，再比较胜利分数。本例不涵盖扩展引入的特殊规则。

我们可以把其设计问题重构为：“玩家如何在提高未来购买能力与取得终局分数之间选择时机？”这是本课的分析，不冒称作者公开陈述的全部设计目标。

关键不只是“有很多牌可买”。新牌进入未来的抽牌系统，购买会改变以后遇到什么；胜利牌又把目标本身带进这个系统。多买资源牌可能提高未来购买力，却不能直接替代终局分数。过早大量买入不提供即时购买力的胜利牌，则可能降低后续手牌的经济表现。临近结束时，未来收益来不及兑现，当前得分的意义便改变了。

由此可能出现不同购买时机、对剩余供应量的关注和对对手进度的判断。但不能推出“永远后期才买胜利牌”或“牌库越薄越好”；供应组合、回合限制、对手行动及特殊得分会改变答案。W06 才会量化特定牌库的抽牌概率，本周先理解因果链。

可迁移的原则是：长期目标可以和执行短期动作所用的系统相互影响。若你的 DBG 新卡只是收藏数量增加，却不改变后续可用动作、资源或目标，那么构筑可能尚未真正进入核心决策。

### D2 从零设计：海岸决斗 0.1

这是本教材自创的纸面模型，**不是 ActionDBG 当前规则说明，也不要求修改游戏代码**。目标是让玩家能解释何时争取击杀、何时降低伤害。本版先移除计时、动画、抽牌、冷却与反击，降低需要同时理解的规则数量。

完整规则如下：

1. 一名玩家对抗规则控制的敌人。玩家初始生命 6，敌人初始生命 8；全部信息公开，玩家先手。
2. 每次玩家回合开始，行动点设为 3，三张固定牌恢复可用，护盾设为 0。剩余行动点不结转；不发生抽牌或构筑。
3. 玩家可依次打出合法牌，逐张立即支付并结算，也可主动结束回合。每张牌每个玩家回合最多使用一次；不能支付则不能打出。
4. 快斩费用 1，造成 2 伤害；重斩费用 2，造成 3 伤害；格挡费用 1，获得 2 护盾。护盾只抵挡接下来的敌方攻击，不跨回合保留。
5. 玩家结束回合后，若敌人尚存活，它进行一次 3 点伤害的攻击。实际伤害为 `max(0, 3－护盾)`，随后护盾清零，进入下个玩家回合。
6. 每次伤害后立即检查生命。敌人生命小于等于 0 则立即胜利并取消其后续攻击；玩家生命小于等于 0 则立即失败。本模型不存在同时伤害。

这已经足够两人分别担任玩家与记录员执行。记录员只按规则处理，不替玩家选择。

先比较“玩家生命 2、敌人生命 8”的局面：

| 本回合方案 | 花费 | 敌方生命变化 | 随后玩家受到的伤害 | 本回合结果 |
| --- | --- | --- | --- | --- |
| 快斩＋重斩 | 3 | 8 → 3 | 3 | 玩家死亡，失败。 |
| 重斩＋格挡 | 3 | 8 → 5 | 1 | 玩家剩 1 生命，继续。 |
| 快斩＋格挡 | 2 | 8 → 6 | 1 | 玩家剩 1 生命，继续，余下 1 点不结转。 |

第二行说明防守能避免立即失败，不代表已经保证最终胜利。第三行在这个无其他效果、无资源结转的模型中，比第二行少造成伤害却没有获得额外防守；它不因“也是一个组合”就自动成为同等有价值的策略。

现在只把敌方生命改成 4。快斩＋重斩会在敌人攻击前击杀，玩家保留 2 生命；重斩＋格挡使敌人剩 1 生命，随后玩家损失 1 生命。情境改变了选择的后果，而不是设计师宣布哪张牌更高级。

这里可能产生按局面进攻或防守的行为，但尚未证明完整模型有长久深度。它可能很快被解成固定流程。可迁移的原则是：先构造两个确实会改变理由的局面，验证决策差异，再决定是否增加牌；不要仅凭两种组合都能获胜，就声称策略丰富。

### D3 失败设计：拥有三个按钮，却总有一个显然更好

假设目标是让玩家在同一个反应窗口中权衡攻守，且每次只能选一个方案：免费反击，取消全部来袭伤害并对敌造成 4 伤害；付费格挡，支付 1 点，仅减少 2 点来袭伤害；放弃，不改变结果。

再明确前提：反击对所有攻击都合法，没有时机失败、冷却、其他代价或负面效果；敌人不会因受到伤害而获得好处。此时反击比其他方案免伤更多、输出更多、花费更少。理解规则后一直选择它，是对目标的合理响应，不是玩家缺乏创造力。

修正不必一律“削弱反击”。可以加入确实不同的适用条件或代价，也可以承认作品目标就是让玩家轻松展示强大能力。如果增加难以判断的失败时机，选择可能变成操作风险管理，而非原来的资源取舍；要重新说明想训练哪种能力。

可迁移的原则是：先写清比较前提，再诊断选择是否失去意义；修正必须服务于目标，不能只为了让统计上每个按钮都有人按。

## E 可执行的设计方法

### E1 六步完成一张决策分析表

这是本课综合提出的工作法，不属于某位作者的命名理论。

1. **限定对象。** 写清是哪个玩家、什么局面、什么目标，不分析抽象的“所有战斗”。
2. **记录信息。** 分开列完整状态、玩家已知、未知内容，避免事后视角。
3. **列合法方案。** 包含结束回合、暂不行动等真正允许的行为；剔除费用不足的组合。
4. **逐项结算。** 记录费用、即时结果、敌方后续行动和终止检查，不跳过不利分支。
5. **比较理由。** 问每个方案在何种目标下可能被选中；没有理由时，检查是否真的缺少条件，而非替它编故事。
6. **提出反例。** 改变一项相关状态，寻找结论是否仍成立，再把有待试玩的体验假设单独写出。

可复用的表头是：`规则版本｜当前状态｜玩家已知｜合法方案｜即时后果｜后续机会｜选择理由｜待验证解释`。没有数值依据的预期，也可以记录，但应标注推测。

### E2 用一次盲读检查规则

让没有参与设计的人先阅读规则并尝试执行，你只记录，不立即讲解。出现停顿时，记录他当时看到什么、问了什么、如何理解；需要澄清就给出必要说明，并把本轮标记为“经主持人解释”，不能继续声称规则完全独立可用。

优先追问可观察问题：“你现在认为有哪些合法行动？”比“你是不是觉得反击很刺激？”更能区分理解和感受。修订时先解决阻止执行的歧义，再处理体验问题。W12 会进一步学习招募、任务和访谈设计，本周的一次盲读只用于发现明显缺口。

## F 实践练习

先独立完成，再阅读 G 部分。开放题允许不同解法，但必须能执行和被检查。

### F1 基础理解

1. 把下列句子分别标成体验目标、游戏目标、规则或实现：“玩家读懂意图后感到聪明”“敌人归零即胜利”“反击只能在命中前使用”“用 C# 事件通知 UI”。解释理由。
2. “这张牌费用 2、伤害 3”是否已经足够让他人执行？写出还缺少的三个条件。

### F2 机制分析

按海岸决斗 0.1，推演两种状态：玩家生命 2／敌人生命 8，以及玩家生命 2／敌人生命 4。分别执行快斩＋重斩、重斩＋格挡，写出每次伤害后的状态和结束位置。再指出 D3 的结论依赖哪些前提。

### F3 开放设计

只修改海岸决斗的一条规则，尝试让原先缺少使用理由的一种方案获得情境价值。给出两个比较局面、完整新规则和你预期的行为。不能只写“提高策略性”；也不要求你的方案优于其他同学。

### F4 与自己的 DBG 项目连接

提交约 1–2 页规则说明 0.1、一张决策分析表、两条推演和一次盲读记录。选择实际项目或纸面分支均可，必须标明版本与差别。重点核对行动点恢复时机、反击合法性、死亡后未执行行动的处理。

若暂时找不到测试者，可先完成纸面推演并标注外部盲读未完成；不要编造玩家反馈。画面、代码和新增卡牌数量不计为作业完成证据。

## G 知识评估与参考解析

### G1 基础题解析

F1 四句依次是体验目标、终止／胜利规则所表达的游戏目标、合法性规则、实现方式。“敌人归零即胜利”也确实是一条规则，分类维度有重叠；能解释它同时规定目标和终止，比机械选择单一标签更好。

F1 第二题可补：使用阶段、合法目标、费用支付时点、每回合可用次数、伤害后的死亡检查等。列出任何三个真正影响执行的问题即可，不要求与你的同学相同。

F2 第一种状态中，快斩后敌人 6、重斩后 3，敌人攻击使玩家生命变为 $2-3=-1$ 而失败；重斩＋格挡后敌人 5、玩家受到 1 伤害而剩 1。两种出牌顺序在本模型中不改变各自结果，因为没有额外触发或同时伤害。

第二种状态中，快斩后敌人 2，重斩后死亡，立即胜利，不再接受敌方攻击；重斩＋格挡后敌人 1、玩家 1，尚未结束。把“当前没死”写成“最终必胜”，或让死亡敌人继续攻击，都是需要订正的错误。

### G2 开放题怎样评价

F3 可以考虑让未用行动点有明确后续用途，使快斩＋格挡剩下的一点资源形成差别；也可以改变敌人反应规则。但仅写“资源可以留着”仍不完整：保留到何时、上限多少、如何使用、与恢复关系是什么，都要写清。这个例子是候选方向，不是标准答案，更不是项目改动要求。

用以下标准审查答案：新规则是否明确；两个局面是否真正导致不同后果；是否解释了代价；是否引入未处理的循环或必选项；是否把预期与观察分开。只增加随机数而没有解释它服务的判断，不算充分论证。

### G3 检查清单与进入下一周的门槛

- [ ] 能区分体验、目标、规则和实现，并接受合理的分类重叠。
- [ ] 能用形式元素描述真实游戏，不用题材介绍代替规则。
- [ ] 能列出决定当前动作是否合法的状态和信息。
- [ ] 推演完整处理扣费、效果、敌方行动与死亡。
- [ ] 能说明一个选项何时缺少理由，以及结论在哪些条件下失效。
- [ ] 规则说明支持他人执行，或如实记录盲读尚未完成。
- [ ] 不把自己的设计愿望、一次观察和普遍结论混写。

建议自评：概念与分析 25 分、规则完整 25 分、推演正确 20 分、验证记录 20 分、边界与表达 10 分。达到 80 分且无关键执行矛盾，可以进入 W02；这是教学门槛，不是科学测量。未完成外部盲读时可以先阅读 W02，但保留该项未完成状态，不能把 W01 项目作业标为已验证。

## H 总结与下一周

### H1 核心概念速查

| 中文术语 | 英文 | 本周需要记住的关系 |
| --- | --- | --- |
| 游戏设计 | Game Design | 组织行动、限制、信息和后果，体验仍需验证。 |
| 形式元素 | Formal Elements | 从参与结构到结果检查系统骨架。 |
| 体验目标／游戏目标 | Experience Goal／Game Objective | 希望玩家感受什么，不等于系统认可什么结果。 |
| 规则／程序 | Rules／Procedures | 前者约束与改变局面，后者组织执行流程。 |
| 游戏状态／动作 | Game State／Action | 依照规则，从当前局面执行合法变化。 |
| 信息 | Information | 完整状态不等于玩家决定时知道的内容。 |
| 资源 | Resource | 限制和支持行动，其时机与去向比名字重要。 |
| 有意义的游戏行为 | Meaningful Play | 注意行动结果是否可辨认、是否影响系统。 |
| 假设／观察 | Hypothesis／Observation | 预期解释与实际记录要分开保存。 |
| 试玩测试 | Playtesting | 用实际执行检验规则和体验主张，而非寻找赞同。 |

### H2 设计原则与知识衔接

先把局面写清，再评价选择；先保证别人能执行，再论证体验；先找结论的前提和反例，再扩大内容。形式分析帮助发现问题，但不能独自证明一款作品的全部价值。

下一周会用 MDA 明确连接机制、实际动态与体验，并审查本周提出的因果链。请带着规则说明、两条推演及至少一个“结果与原先预期不同”的问题继续，而不是带一份必须被证明正确的设计。

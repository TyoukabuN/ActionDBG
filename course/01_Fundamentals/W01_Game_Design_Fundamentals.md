# W01 游戏设计基础：把想象中的体验写成可执行的规则

所属课程：[16 周课程大纲](../00_Curriculum.md)。建议学习时间：6–8 小时。版本：1.1；日期：2026-11-03。

你脑中也许已经有一场精彩的战斗：敌人挥剑，画面减速，玩家抓住机会出牌。接下来，要把这段体验写成别人能照着玩的规则。

本周就从这里开始。先不急着计算抽牌概率或设计完整成长系统，而是选出一场小型对局，把玩家能做什么、怎样结算、何时结束说清楚。你不坐在旁边解释时，另一个人也应该能完成这一局，并说出自己为什么这样选。

## A 学习目标

学完本周，你应能完成以下几件事：

1. 分清目标体验、游戏目标、规则、执行程序和实现方式，知道“战斗很爽”还需要哪些机制说明。
2. 从玩家、目标、资源、冲突、边界和结果入手，拆解一款卡牌游戏。
3. 针对一次选择，写出当前状态、已知信息、合法动作、结算顺序和不同后果，找出尚未说清的地方。
4. 结合具体情境，解释选项数量和策略选择之间的区别。
5. 写出一份能独立执行的纸面规则，推演两条不同决策路径，并记录一次外部试玩的观察与疑问。

完成这些工作，就有了可检查的学习成果。本周先验证规则和决策，不要求你证明长期趣味性，也不要求实现新功能。

## B 前置知识与程序员视角的调整

变量、条件判断和执行顺序，都能帮助你理解游戏规则。玩家有 3 点行动点，是当前状态的一部分；必须支付 2 点才能重斩，是一个合法性条件。本周只需要基础算术和这种顺序推理。

但程序按规则运行以后，还有问题需要回答。设想你已经写好卡牌结算器：每张牌准确扣费，伤害计算无误，动画也能完整播放。所有攻击牌的费用和其他条件都相同，只有伤害高低不同。理解规则后，玩家很可能只选伤害最高的一张。

结算器没有出错，这组牌却可能缺少你希望玩家思考的取舍。检查这种问题，纸上的几个数字就够了，可以在完整界面做出来之前进行。

从现在开始，记录设计时把下面三件事分开：

- **发生了什么**：玩家连续三次选择攻击。这是观察。
- **为什么发生**：玩家觉得格挡不划算。这是一种解释，还需询问或其他证据支持。
- **希望发生什么**：你希望玩家在攻防之间犹豫。这是设计意图。

它们会出现在同一份笔记里，但不能互相替代。

## C 核心理论

### C1 游戏设计在设计什么

沿用开头的战斗想象。你想加入反击牌，让玩家觉得自己读懂了敌人的破绽。要把它做成规则，至少要说明：什么时候能反击，需要支付什么，成功后怎样改变局面。

这些规则可以由设计者直接规定。玩家是否看懂机会、是否愿意反击、是否把成功归因于自己的判断，则需要通过试玩了解。你能规定每回合最多出两张牌，却不能规定玩家一定紧张。新手可能困惑，熟练玩家可能很快算完，也有人会喜欢从容规划。

因此，本课采用这样的工作定义：**游戏设计（Game Design）是在特定参与情境中，组织玩家的行动、限制、信息和后果，让他们开展某种活动，并检验这些活动能否带来预期体验。** 定义中的“检验”提醒我们，设计意图还不是玩家已经获得的感受。这也会成为 W02 学习 MDA 的起点。

这不是关于所有游戏的最终定义。“什么算游戏”在研究中仍有争论。有的定义强调规则、冲突与可量化结果，有的重视自愿参与、虚构情境或游戏态度。叙事探索、沙盒和角色扮演会使这些边界更难划定。当前的工作定义用于分析 DBG，并不要求所有游戏都有输赢、敌人或有限资源。

### C2 用形式元素找到系统骨架

先暂时放下角色造型和战斗特效，看看这局游戏由什么组成：谁参与，想达到什么目标，可以做什么，又受到什么限制。这样的检查会用到形式元素（Formal Elements）。Fullerton 的教材把它作为分析游戏的重要入口。

下表用自己的语言整理这些维度，帮助你读懂一套规则，并非原著的逐字定义。

| 元素 | 要回答的问题 | 在卡牌战斗中的具体含义 |
| --- | --- | --- |
| 玩家 Players | 谁参与、谁控制什么、参与者怎样关联？ | 玩家控制角色，敌人按规则行动；是否合作或竞争需明确。 |
| 目标 Objectives | 玩家想达成什么结果？ | 击败敌人、保护目标或满足特殊条件，不能只写“不断出牌”。 |
| 程序 Procedures | 行动按什么流程展开？ | 谁先行动、何时选牌、何时结算、何时进入下一回合。 |
| 规则 Rules | 哪些状态合法、何种动作被允许、后果如何产生？ | 费用不足不得出牌；攻击造成伤害；死亡后不继续行动。 |
| 资源 Resources | 什么会被获取、占用、支付或失去？ | 生命、行动点、手牌、抽牌机会；不同资源恢复方式不同。 |
| 冲突 Conflict | 什么阻碍目标达成？ | 敌人伤害、有限行动预算、相互排斥的选择，而不只是画面上的打斗。 |
| 边界 Boundaries | 哪些人、信息与行为属于本局？ | 是一场遭遇还是整段冒险？局外选择是否影响本局？ |
| 结果 Outcome | 系统怎样识别结束，如何评价结果？ | 胜负、得分、是否保留剩余生命；没有定义的指标不自动算成绩。 |

不要把填完八行当成分析结束。各项之间需要接得上。例如，你把生命列为资源，就继续追问：它怎样损失，能否恢复，归零后会发生什么？写出了资源名称，尚未交代它在游戏中起什么作用。

目标也会影响我们怎样看待资源。若一局只判定胜负，生命既不跨局继承，也不计入终局得分，那么“获胜时尽量保留生命”可能是玩家个人偏好，不一定是规则给出的激励。分析选择时，要知道自己讨论的是哪一种目标。

形式分析能帮助你检查这些关系，但无法单独解释角色身份、音乐和文化背景怎样赋予行动意义。暂时抽去题材，是为了看清规则；到了 W09–W10，还要把玩家的理解和信息呈现一起考虑。

### C3 区分四种常被混写的目标

“让玩家觉得自己因读懂敌人而取胜”和“在自己死亡前击败敌人”听起来很接近，实际承担不同作用。前者描述希望产生的体验，后者规定游戏认可的结果。

第一种叫体验目标（Experience Goal）。例如，你希望熟悉回合制的新手觉得自己的判断起了作用。它能指导设计，却不能直接用一个布尔值判断是否达成。

第二种是游戏目标（Game Objective）。例如，在自己的生命归零前，使敌方生命归零。这会影响玩家把什么视为好结果，以及愿意为此付出什么。

第三种是局部目标。玩家可能暂时攒钱买牌，或设法避开本次伤害。这些办法要服从整体目标，也可以随局面改变。如果本回合击杀就能获胜，继续防守也许已经没有必要。

第四种是项目目标，属于设计者这次要研究或交付的工作。比如，你想验证玩家是否看得懂反击窗口。若为了方便观察，强迫玩家按指定顺序出牌，测试到的可能只是他会不会服从教程，不能据此认定他会自然选择反击。

检查目标时，可以问：它们发生冲突，规则会奖励什么？如果口头上鼓励冒险，却按每点受伤永久扣分，玩家谨慎行动就很容易理解。先检查激励是否一致，再判断玩家是否误解了玩法。W07 会继续讨论这种取舍的价值。

### C4 状态、动作与结算：让规则能被执行

分析一场简化的决斗，可以先记下双方生命、轮到谁行动、剩余行动点、可用牌、护盾和回合数。规则要根据当前局面决定接下来的变化。我们把描述这个局面、决定后续变化所需的信息，称为游戏状态（Game State）。

要不要把某项信息放进状态，得看它是否影响规则。如果背景石柱的颜色不影响规则，这个模型就可以略去它。隐藏的下一张牌虽然玩家看不到，却仍可能属于完整状态。

玩家通常只知道状态中的一部分。评价他当时的选择，要依据决定之前已经公开或可以推断的信息。把结算后才揭示的牌也算进他的知识，会把实际决策误判成没有选中事后答案。

动作（Action）是玩家或系统可以进行的一次操作。点击重斩按钮，不一定意味着成功打出重斩：费用不足时，输入可以发生，规则仍应拒绝出牌。你要写清的，是它何时成为一个已经支付、需要执行的行动。

用一个简单记法表示结算前后的关系：

$$
s_{t+1}=T(s_t,a_t)
$$

$s_t$ 是结算前的状态，$a_t$ 是合法动作，$T$ 是状态转换规则。沿着这个记法读，就能追问：当前局面允许什么操作，这次操作又会把局面变成什么样？

它只是帮助记账的最小模型。如果包含随机抽牌，变化还依赖随机结果；如果双方同时决定，也不能只用一个人的动作描述整个过程。写出公式以后，仍需把这些条件补上。

再看一个很小的例子：敌人只剩 2 点生命，重斩造成 3 点伤害。敌人死亡后，原本准备发动的攻击还会继续吗？你可以设计不同顺序，但必须选定一种。只写“双方发动攻击”，别人无法据此重现结果。

### C5 规则不仅是牌上的效果文字

一张反击牌写着“取消敌方攻击并造成 2 点伤害”，读者仍可能不知道怎样执行。哪些攻击能触发？是在命中前还是命中后使用？支付普通行动资源吗？付不起费用时还开启窗口吗？双方同时死亡又怎样处理？

这些空缺最终总会被填上。如果设计没有说明，程序员、玩家和主持人就可能各填一套，得到不同的游戏。

为方便检查，本课把问题分成四组：合法性、结算、信息和终止。合法性管何时能做什么；结算管支付、目标和效果的顺序；信息管玩家在决定前后看得到什么；终止管何时停止、怎样判定结果。这是教学用的检查工具，不是某本书的通用分类。

执行程序还要与规则一致。“玩家回合 → 敌人回合”交代流程，“普通牌只能在自己的回合使用”交代约束。写作时可以分开说明，但推演时要把它们放在一起检查。流程允许进入反击阶段，却找不到任何合法反击动作，就还没有写完整。

资源恢复尤其值得逐步推演。“己方回合结束时恢复”和“下次己方回合开始时恢复”，会使玩家在敌方回合拥有不同的资源。只比较行动点上限，很容易漏掉这层差别。界面未必需要展示每个内部细节，设计者却要清楚它们怎样影响选择。

### C6 什么样的选择具有设计意义

玩家面对几个按钮时，先要看它们是否对应不同的可执行方案，这是讨论选择（Choice）的起点。要判断是否形成了决策（Decision），还需看他怎样依据目标和信息，预期后果并作出取舍。选项数量、排列组合或输入频率，都不能直接代表策略深度。

Salen 与 Zimmerman 讨论有意义的游戏行为（Meaningful Play）时，强调行动与结果的关系，包括结果是否可辨认、是否整合进更大的游戏系统。借用这个思路，可以检查两件事：玩家知道变化与自己的行动有关吗？这次变化会影响之后的局面或目标吗？这两问是本课的转述和应用，不能独自概括所有有意义选择。

例如，重斩比快斩造成更多伤害，界面却只播同样的光效，玩家可能看不出差别。如果两张牌只是火焰颜色不同，之后的状态完全一样，它们也许满足了表达偏好的需要，却未必增加战术取舍。两种价值都可以存在，分析时要说清是哪一种。

再考虑两张同费牌：甲造成 4 伤害，乙造成 2 伤害。假设可用条件、目标、次数和其他后果全部相同，唯一目标是尽快降低敌方生命，那么乙在这些前提下不占优势。我们暂称它被甲支配，严格条件留到 W08。若乙能抽牌、绕过护甲或避免反伤，比较条件就变了，不能继续只盯着伤害数字。

不过，清楚的好选择也能服务于学习。新手识别出一张明显合适的牌，熟练玩家顺畅执行已经掌握的组合，都可能是你希望出现的体验。需要检查的是：随着理解加深，游戏是否仍提供符合目标的判断，这些判断花费的精力是否值得。无需让玩家每秒都陷入纠结。

### C7 策略深度、复杂度与不确定性

你可以增加三种费用和十种关键词，让牌之间出现更多组合。玩家因此需要记住更多东西，但还不能说明他获得了更丰富的判断。如果一种组合在所有相关情境中都明显最好，新增复杂度可能没有达到预期。相反，少量规则也可能借助时机、位置、对手和资源形成许多取舍。

检查不确定性时，也要知道它来自哪里。洗牌会带来随机结果；隐藏敌方计划，会使玩家缺少信息；即使规则与局面全部已知，也可能来不及穷尽后果。这属于计算和推理上的困难。三者可以同时存在，却不能用同一种办法处理。说明界面能改善信息表达，但不会消除洗牌的随机性。

本周先不计算抽牌概率，而是追问随机或未知的作用。它有没有促使玩家调整计划，能否形成可管理的风险，玩家又能否理解损失的原因？完全确定的短决斗可以是有价值的战术谜题，随机发牌的对局也可能每次都只有同一个答案。“每局不一样”还不足以证明耐玩。

### C8 从设计主张到可反驳的问题

写下“反击很有趣”以后，下一步该观察什么，并不清楚。可以先把问题收窄：首次接触规则的玩家，看到攻击提示后，能否说明自己为什么选择反击或放弃？这件事更容易观察，不过即使玩家能解释，也还没有证明紧张感或长期耐玩性。

本课建议把主张写成四项：预期行为、发生条件、观察办法，以及什么证据会让你重新考虑。比如，你预计玩家遇到高威胁时会防守。先确认威胁已经公开、玩家理解防守规则，再记录他的出牌和解释。如果他认为不论威胁高低都只有一个可行选项，就要回头检查机制是否真有情境差异。

这样做，是给自己的判断留下修改余地。观察不符合预期时，你才知道应该从哪一个条件继续查。

## D 案例研究

### D1 成熟游戏：Dominion 为什么把得分牌放进牌库

在 Dominion 中，买到一张得分牌，会改变之后抽到的手牌。得分目标和每回合执行动作所用的牌库，就这样发生了联系。

先看规则。本例依据基础游戏第二版，限于双人、无扩展情形。每人用 7 张铜币（Copper）和 3 张庄园（Estate）组成起始牌库，洗牌后抽 5 张。回合依次进行行动、购买和清理，默认有一次行动、一次购买机会，卡牌可以改变它们。清理时弃掉手牌和已打出的牌，再抽 5 张；牌库不足时，按规则利用弃牌堆洗牌继续抽。

普通购买得到的牌进入弃牌堆，通常不能立刻在本回合使用。基础胜利牌庄园、公国、行省会贡献终局分数，却通常不提供当回合的行动或购买力。回合结束时检查结束条件，包括行省堆耗尽或任意三堆供应牌耗尽，之后比较胜利分数。这里不讨论扩展的特殊规则。

于是，买牌时要考虑时间。资源牌可能改善未来的购买力，但不能直接替代终局分数；过早买入大量不提供即时购买力的胜利牌，又可能使之后的手牌更难赚钱。接近结束时，未来收益来不及兑现，眼下得分就有了不同的分量。

我们可以据此提出一个设计问题：怎样让玩家权衡未来购买能力和终局分数的取得时机？这是本课对机制的分析，并不冒称作者公开陈述的全部设计目标。

这些规则可能促使玩家调整购买时机，留意供应量和对手进度。它们却不能证明“胜利牌永远留到后期买”或“牌库越薄越好”。供应组合、回合限制、对手行动和特殊得分，都可能改变答案。到 W06，我们再为特定牌库计算抽牌概率。

对自己的 DBG，可以沿着同一条关系检查：获得新卡后，玩家未来能做的动作、资源或目标有没有改变？如果只增加了收藏数量，构筑可能还没有真正影响核心决策。这里值得借鉴的是长期目标与短期执行系统之间的联系。

### D2 从零设计：海岸决斗 0.1

接下来，用一套小规则亲手推演。这个“海岸决斗”是本教材自创的纸面模型，独立于 ActionDBG 当前玩法，不要求你修改游戏代码。我们要检查，什么局面值得争取击杀，什么局面需要降低伤害。

先去掉计时、动画、抽牌、冷却和反击，把注意力放在三张牌的选择上。

1. 一名玩家对抗规则控制的敌人。玩家初始生命 6，敌人初始生命 8；全部信息公开，玩家先手。
2. 每次玩家回合开始，行动点设为 3，三张固定牌恢复可用，护盾设为 0。剩余行动点不结转；不发生抽牌或构筑。
3. 玩家可依次打出合法牌，逐张立即支付并结算，也可主动结束回合。每张牌每个玩家回合最多使用一次；不能支付则不能打出。
4. 快斩费用 1，造成 2 伤害；重斩费用 2，造成 3 伤害；格挡费用 1，获得 2 护盾。护盾只抵挡接下来的敌方攻击，不跨回合保留。
5. 玩家结束回合后，若敌人尚存活，它进行一次 3 点伤害的攻击。实际伤害为 `max(0, 3－护盾)`，随后护盾清零，进入下个玩家回合。
6. 每次伤害后立即检查生命。敌人生命小于等于 0 则立即胜利并取消其后续攻击；玩家生命小于等于 0 则立即失败。本模型不存在同时伤害。

你可以请另一人担任记录员。由你选择行动，记录员照规则扣费和结算，不替你决定。

把当前局面设为“玩家生命 2、敌人生命 8”，先比较下面三种方案：

| 本回合方案 | 花费 | 敌方生命变化 | 随后玩家受到的伤害 | 本回合结果 |
| --- | --- | --- | --- | --- |
| 快斩＋重斩 | 3 | 8 → 3 | 3 | 玩家死亡，失败。 |
| 重斩＋格挡 | 3 | 8 → 5 | 1 | 玩家剩 1 生命，继续。 |
| 快斩＋格挡 | 2 | 8 → 6 | 1 | 玩家剩 1 生命，继续，余下 1 点不结转。 |

快斩加重斩能多打伤害，但敌人还有生命，仍会攻击。玩家只有 2 点生命，无法承受这次伤害。重斩加格挡能让玩家以 1 点生命继续，不过还不能据此说最终会赢。

再看快斩加格挡。它比重斩加格挡少造成伤害，却没有多获得防守。剩下的一点行动点又不能结转，牌也没有其他效果，因此这个方案在该模型里缺少额外使用理由。能组成另一套出牌顺序，并不自动让它成为同样有价值的策略。

现在保留玩家生命 2，只把敌人生命改为 4。快斩加重斩会在敌人攻击前将其击杀，玩家不受伤，仍有 2 生命。若选择重斩加格挡，敌人会剩下 1 生命并发动攻击，玩家也只剩 1 生命。同样两套牌，因为局面改变，选择理由就变了。

这给了我们一个可以进一步测试的起点：玩家是否会按局面进攻或防守？但还不能据此断言模型耐玩。它可能很快被解成固定流程。先找到两个能改变选择理由的局面，再考虑增加卡牌，比仅仅展示“两套组合都能获胜”更能说明你研究了什么。

### D3 失败设计：拥有三个按钮，却总有一个显然更好

假设你希望玩家在同一个反应窗口里权衡攻守，每次只能选择一个方案。现在有三项：免费反击，取消全部来袭伤害并对敌造成 4 伤害；付费格挡，支付 1 点，只减少 2 点来袭伤害；放弃，不改变结果。

还要把比较条件说全。反击对所有攻击都合法，不会因时机失误而失败，没有冷却、其他代价或负面效果；敌人也不会因为受伤得到好处。

在这些前提下，反击的免伤、输出和花费都更有利。玩家理解以后一直选它，是可以预期的。三个按钮没有带来原本想要的攻守取舍。

如何改，要回到目标。可以给反击不同的适用条件或真实代价，也可以承认这款作品就是希望玩家轻松展现强大能力，不一定都要削弱反击。若增加一个难以把握的失败时机，玩家可能开始管理操作风险；这与原本的资源权衡已有区别，需要重新说明设计目的。

这个案例提醒我们，先限定比较条件，再判断选择是否有问题。改动应帮助游戏达到目标，无需为了让每个按钮的使用率好看而硬凑平衡。

## E 可执行的设计方法

### E1 六步完成一张决策分析表

回到自己的项目时，可以按下面六步分析一次选择。这是本课综合提出的工作法，不是某位作者的命名理论。

1. **限定对象。** 写下哪个玩家处在什么局面、想完成什么目标。先分析一件具体的事。
2. **记录信息。** 分开记录完整状态、玩家已知和未知内容，检查自己有没有带入事后信息。
3. **列合法方案。** 除了出牌，也包括规则真正允许的结束回合或暂不行动。先排除付不起费用的方案。
4. **逐项结算。** 顺着费用、即时结果、敌方后续行动和终止检查，把有利与不利分支都走完。
5. **比较理由。** 在什么目标下，玩家会愿意选这个方案？若找不到理由，检查是否漏了条件，不要替它编一个用途。
6. **提出反例。** 改变一项相关状态，看看原先结论还成立吗。需要试玩才能判断的体验，另外记为假设。

可以复用这个表头：`规则版本｜当前状态｜玩家已知｜合法方案｜即时后果｜后续机会｜选择理由｜待验证解释`。有些预期暂时没有数值支持，也可以记下来，但要标为推测。

### E2 用一次盲读检查规则

请一个没参与设计的人读规则并尝试执行。起初先观察，不立即替他解释。读者停下来时，记下他看到了什么、问了什么、把规则理解成什么。

如果必须澄清，就给必要说明，并记录“经主持人解释”。这并不妨碍测试继续，但不能再用本轮证明规则已经可以独立执行。

提问也会影响你得到的材料。问“你现在认为有哪些合法行动？”，能帮助检查理解；直接问“你是不是觉得反击很刺激？”，很难分辨读者是在说自己的感受，还是顺着问题回答。

先修复阻止执行的歧义，再检查体验。W12 会进一步讲招募、任务和访谈，本周的一次盲读先用于发现明显缺口。

## F 实践练习

先做题，再看 G 部分。开放题可以有多种答案，写出来的方案都需要能执行、能检查。

### F1 基础理解

1. 把下列句子分别标成体验目标、游戏目标、规则或实现：“玩家读懂意图后感到聪明”“敌人归零即胜利”“反击只能在命中前使用”“用 C# 事件通知 UI”。解释理由。
2. “这张牌费用 2、伤害 3”是否已经足够让他人执行？写出还缺少的三个条件。

### F2 机制分析

按海岸决斗 0.1，推演两种状态：玩家生命 2／敌人生命 8，以及玩家生命 2／敌人生命 4。分别执行快斩＋重斩、重斩＋格挡，写出每次伤害后的状态和结束位置。再指出 D3 的结论依赖哪些前提。

### F3 开放设计

只改海岸决斗的一条规则，让原先缺少使用理由的一种方案获得情境价值。写出完整新规则，并用两个局面比较它的后果，说明你预期玩家会怎样选。方案不必比别人的更好，但“提高策略性”需要落实成这些可以检查的变化。

### F4 与自己的 DBG 项目连接

提交约 1–2 页规则说明 0.1、一张决策分析表、两条推演和一次盲读记录。可以分析实际项目，也可以用纸面分支，但要写明版本和差别。尤其检查行动点何时恢复、何时允许反击，以及死亡后尚未执行的行动怎样处理。

暂时找不到测试者，就先完成纸面推演，把外部盲读记为未完成。等到实际进行后再补记录。新增画面、代码或卡牌数量，都不能代替这些作业成果，也不要编造玩家反馈。

## G 知识评估与参考解析

### G1 基础题解析

F1 的四句话，依次对应体验目标、终止／胜利规则所表达的游戏目标、合法性规则和实现方式。不过，“敌人归零即胜利”同时也是一条规则。能解释它既规定目标又规定结束，比强行只归入一类更有意义。

第二题可以补使用阶段、合法目标、费用支付时点、每回合使用次数或伤害后的死亡检查。写出任意三个真正影响执行的条件即可，答案不必完全相同。

F2 的第一种状态中，快斩后敌人剩 6，重斩后剩 3。它仍能发动攻击，使玩家生命变为 $2-3=-1$，因此玩家失败。选择重斩加格挡时，敌人剩 5，玩家受到 1 点伤害，剩 1 生命。

第二种状态中，快斩后敌人剩 2，重斩使它死亡，对局立即胜利。敌人不再攻击。重斩加格挡则留下敌人 1 生命，攻击后玩家也剩 1，对局继续。

在这个没有额外触发或同时伤害的模型里，各组合中的两张牌交换顺序，不改变各自的结果。检查答案时，留意自己有没有把“本回合活下来”误写成“最终必胜”，或让已经死亡的敌人继续攻击。

### G2 开放题怎样评价

F3 的一个候选方向，是让未用行动点在之后有明确用途。这样，快斩加格挡留下的一点资源，才可能与重斩加格挡形成区别。你也可以研究敌人的反应规则。

但“资源可以留着”还不够别人执行。你仍要交代留到何时、上限多少、如何使用，以及与原有恢复时机怎样衔接。这个方向只是候选，不是唯一答案，也不要求修改正式项目。

评价方案时，逐项看看：新规则说清了吗？两个局面真的产生了不同后果吗？代价是什么？有没有引入未处理的循环或必选项？哪些是预期，哪些已经观察到？只增加随机数，却没解释它让玩家多判断了什么，还不能算充分论证。

### G3 检查清单与进入下一周的门槛

- [ ] 能区分体验、目标、规则和实现，并接受合理的分类重叠。
- [ ] 能用形式元素描述真实游戏，不用题材介绍代替规则。
- [ ] 能列出决定当前动作是否合法的状态和信息。
- [ ] 推演完整处理扣费、效果、敌方行动与死亡。
- [ ] 能说明一个选项何时缺少理由，以及结论在哪些条件下失效。
- [ ] 规则说明支持他人执行，或如实记录盲读尚未完成。
- [ ] 不把自己的设计愿望、一次观察和普遍结论混写。

可以按以下比例自评：概念与分析 25 分、规则完整 25 分、推演正确 20 分、验证记录 20 分、边界与表达 10 分。达到 80 分，且没有影响规则执行的关键矛盾，就可以进入 W02。这是本课的教学门槛，不是科学测量。

若只是外部盲读尚未完成，可以先读 W02，但要保留未完成状态。等补上实际观察后，再判断 W01 项目作业是否通过验证。

## H 总结与下一周

### H1 核心概念速查

| 中文术语 | 英文 | 本周需要记住的关系 |
| --- | --- | --- |
| 游戏设计 | Game Design | 组织行动、限制、信息和后果，体验仍需验证。 |
| 形式元素 | Formal Elements | 从参与结构到结果检查系统骨架。 |
| 体验目标／游戏目标 | Experience Goal／Game Objective | 希望玩家感受什么，不等于系统认可什么结果。 |
| 规则／程序 | Rules／Procedures | 前者约束与改变局面，后者组织执行流程。 |
| 游戏状态／动作 | Game State／Action | 依照规则，从当前局面执行合法变化。 |
| 信息 | Information | 完整状态不等于玩家决定时知道的内容。 |
| 资源 | Resource | 限制和支持行动，其时机与去向比名字重要。 |
| 有意义的游戏行为 | Meaningful Play | 注意行动结果是否可辨认、是否影响系统。 |
| 假设／观察 | Hypothesis／Observation | 预期解释与实际记录要分开保存。 |
| 试玩测试 | Playtesting | 用实际执行检验规则和体验主张，而非寻找赞同。 |

### H2 设计原则与知识衔接

本周分析一套规则，始终在做三件事：写清局面，按顺序执行，再比较选择理由。别人能执行以后，才有机会检查它是否带来了你想要的体验。每个判断都要记住自己的前提，也留意能推翻它的局面。

形式分析仍不能独自说明一款作品的全部价值。下一周，我们会借助 MDA，把机制、实际动态和体验联系起来，继续检查本周的因果判断。带上规则说明、两条推演，以及至少一个与预期不符的问题，让后续学习能接着它往下走。
